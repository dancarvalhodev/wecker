## Problemas encontrados na análise (entram nos passos abaixo)

**Segurança / correção (prioridade alta)**
1. `DockerClient` interpola o `id` recebido do usuário direto na URL (`containers/$id/start`). Um `id` como `../../algo` pode alcançar outros endpoints da API do Docker. → validar formato do id.
2. Cadastro público + nenhum controle de papel = qualquer pessoa na rede pode controlar o Docker do host.
3. Sem proteção CSRF nos `POST`.
4. `dashboard.js` renderiza `name`/`image` sem escapar HTML (XSS via nome de container/imagem).
5. `HttpErrorHandler` testa `instanceof HttpException` (classe global do PECL), não `Slim\Exception\HttpException` → 404/405 viram 500.
6. Admin semeado com senha conhecida em `docs/database.sql`.
7. Postgres e Redis publicados em portas do host sem necessidade.

**Bugs funcionais**
8. Docker sem nenhum container → `DashboardService` lança "not found" e o dashboard quebra (lista vazia `[]` é tratada como falha).
9. Portas montadas errado: `Ports[0]->PublicPort . ':' . Ports[1]->PrivatePort`.
10. Logs vêm no formato multiplexado do Docker (cabeçalho de 8 bytes por frame) sem tratamento; `DockerClient::logs()` chama `header()` (efeito colateral fora do PSR-7); placeholder `'arroz'` no JS.
11. `RegisterValidator` retorna erros que ninguém lê (validação de cadastro nunca bloqueia).
12. `login.js`/`register.js` leem `response.messages`, mas o backend envia `error` e com status 4xx (cai no callback `error`) → mensagens de validação nunca aparecem.
13. `DashboardController` ignora o `DashboardService` injetado; `DashboardService` faz `new DockerClient()` em todo método (impossível testar).
14. Rota `POST /dashboard/create` aponta para método inexistente; template chama `Create.init()` inexistente.
15. Import morto `use function PHPUnit\Framework\matches` em código de produção.

**Dívida de base**
16. Sem `phpunit.xml`, sem análise estática, sem padrão de código automatizado.
17. `minimum-stability: dev` e `guzzle 8.0.x-dev` (dependência instável em produção).
18. Schema só via `docs/database.sql` manual — sem migrações.
19. `APP_ENV` fixo em `development` no `nginx/default.conf` (desde a etapa 4b, no `config/caddy/Caddyfile`).
